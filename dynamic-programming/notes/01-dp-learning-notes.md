# DP 學習反思



## 學習前後的改變



學習以前，我只聽過 DP（動態規劃）這個名稱，但對它沒有實際概念。



現在我理解到，DP 是把一個大問題拆成許多小問題，保存已經算過的小問題答案，再依照題目的需求，用這些答案推導出加總、最小值或最大值。



## 最常遇到的困難



我最常把「前一格」的概念搞混。



後來我發現，不同題目的狀態定義不同，所以「前一格」不一定只是索引減一。例如在二維 0/1 背包中，`dp[i-1][w]` 表示少考慮一件物品，而不是容量少一格。



我透過重新確認狀態定義，並手動畫出 DP 表格與轉移方向，才逐漸弄懂它們的關係。



## 三個重要的實作細節



- INF：在求最小值的問題中表示目前無法到達，避免把不存在的答案誤認成最小值。

- 背包容量倒序：避免同一件物品在同一輪更新中被重複使用。

- 網格遇牆歸零：牆壁沒有任何合法路徑可以到達，也能避免起點初始化為 1，但起點其實是牆的錯誤。



## 最能代表進步的練習



最能代表我進步的是 `07_knapsack_2d.cpp`。



這個練習讓我真正理解二維 DP 中「前一個狀態」的意義，也讓我知道寫轉移式以前，必須先說清楚每一個維度代表什麼。



## DP 與 BFS、DFS 的差異



BFS 和 DFS 主要是在圖或網格中探索節點與路徑。



DP 則是先定義狀態，保存已經算好的子問題答案，再利用狀態轉移推導出更大問題的答案。



這次學習讓我明白，寫 DP 不能只背公式，必須先確認狀態定義、初始值與轉移方式。
