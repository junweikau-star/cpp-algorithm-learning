7/17\~7/25：建立圖論與 BFS 基礎



&#x09;第一次學習的目標是先建立足以撰寫 BFS 的基礎知識。



&#x09;一開始，我先透過小精靈遊戲中「鬼魂尋找玩家」的情境理解 BFS。將鬼魂所在位置當成起點後，BFS 不會選擇一條路一直走到底，而是先搜尋一步能到達的位置，再搜尋兩步、三步能到達的	位置，像水波一樣逐層向外擴散。透過這種方式，我先從直觀情境理解 BFS 的基本運作方式。



&#x09;接著，我學習 BFS 最重要的資料結構 queue。我練習 push()、front()、pop() 與 empty() 等基本操作，並理解 queue 採用 FIFO（First In, First Out，先進先出）的方式處理資料。學	習過程中，我一開始曾誤以為 push() 是從 queue 前方加入，後來才釐清 queue 是從尾端加入、前端取出，也進一步理解這種順序為什麼能配合 BFS 一層一層向外搜尋。





&#x09;在開始寫 BFS 前，我也補充圖論所需要的基本概念，包括節點、邊、無向圖與有向圖，並嘗試把遊戲地圖轉換成圖論模型。例如可以將可以站立的位置視為節點，而兩個可以直接互通的位置	之間建立一條邊。



&#x09;之後，我進一步學習電腦如何儲存一張圖，比較\*\*鄰接表（Adjacency List）與鄰接矩陣（Adjacency Matrix）\*\*的差異。由於競程題目常出現節點很多、實際連線相對較少的情況，因此後續	實作主要採用空間需求約為 O(n+m) 的鄰接表。



&#x09;由於我原本對 C++ STL 還不熟，因此我另外練習 vector<vector<int>> 的宣告、resize()、push\_back()、size() 與迴圈走訪，並將二維 vector 實際應用在鄰接表中。最後，我完成無向圖	建圖練習，理解無向邊 a-b 必須同時記錄 a → b 與 b → a。



&#x09;完成這些基礎後，我第一次自行寫出完整的 C++ BFS 程式，包含讀取圖的資料、建立鄰接表、使用 visited 紀錄是否拜訪過，以及利用 queue 控制搜尋順序。最後再透過測試資料確認 BFS 	能正確輸出走訪順序。



7/26\~8/1：深化 BFS 的概念與應用



&#x09;第二次學習的重點，是讓 BFS 不再只是「把節點走過一次」，而是開始理解 BFS 可以解決什麼問題，以及如何讓程式更有效率。



&#x09;首先，我進一步處理無權圖最短距離問題。原本的 BFS 只需要記錄節點是否走訪過，但如果要知道起點到每個節點的最短步數，就需要加入距離資料。

&#x09;因此，我使用距離陣列 d 紀錄每個節點與起點之間的距離，並使用：

&#x09;d\[start] = 0

&#x09;d\[v] = d\[u] + 1

&#x09;表示從目前節點 u 再走一條邊到鄰居 v。



&#x09;在實作的過程中，我曾將 visited 的值錯誤地放進 queue，而不是把真正的節點編號放入 queue。找出問題後，我重新理解「queue 裡究竟應該儲存什麼資料」，並自行修改程式。



&#x09;接著，我又嘗試將原本的 visited 陣列移除，讓距離陣列本身同時扮演兩種角色：

&#x09;d\[x] == -1：尚未拜訪

&#x09;d\[x] >= 0：已拜訪，而且數值就是最短距離

&#x09;雖然修改時曾一度將 == -1 的判斷條件寫反，但經過測試與除錯後，最後成功完成不需要額外 visited 的版本。



&#x09;除此之外，我也進一步分析 BFS 的時間複雜度。在使用鄰接表的情況下，每個節點最多進出 queue 一次，每條邊也只會被檢查固定次數，因此整體時間複雜度為：O(n + m)



&#x09;之後，我開始理解 BFS 的使用限制。我透過「不同道路需要不同時間」的例子，比較「經過最少邊」與「總花費最少」之間的差異，發現一般 BFS 找到的是最少邊數的路徑。如果每條邊的	成本都相同，它也等於最小總成本；但如果每條邊的權重不同，就需要使用其他演算法，例如之後預計學習的 Dijkstra。

&#x09;經過第二次學習，我已經不只是能把 BFS 寫出來，而是開始理解距離紀錄、資料重複使用、複雜度與 BFS 的適用範圍。



8/2\~8/8：透過三個難度挑戰 BFS 能力



&#x09;完成基礎與深化練習後，我希望確認自己是不是真的理解 BFS，因此第三次學習不再以新的基本觀念為主，而是要求設計三個不同難度的題目，分別從入門、中級到高階測試自己的 BFS 能	力。



&#x09;挑戰一: 單源 BFS

&#x09;第一題是從一個起點出發，計算它到所有節點的最短距離。

&#x09;這一題主要測試我是否能自行整合鄰接表、queue、距離陣列、不連通圖與 O(n+m) 的時間複雜度。我自行完成 C++ 程式，讓起點距離為 0，第一次發現一個新節點時將距離設成前一個節點	加 1，而無法到達的節點則維持 -1。這一題主要是在確認前兩次建立的 BFS 基礎是否已經可以獨立使用。



&#x09;挑戰二：多源 BFS

&#x09;第二題將單一出發點改成多個鬼魂同時從不同位置出發，並在二維地圖中向上下左右擴散。這次我不再為每一個起點分別執行一次 BFS，而是在開始時將所有起點一起放入 queue，使它們同	時向外擴散。透過這題，我將 BFS 從一般節點圖延伸到二維網格，也開始理解\*\*多源 BFS（Multi-source BFS）\*\*的概念。



&#x09;挑戰三：一次破牆 BFS

&#x09;這題是最高難度的。題目要求角色從 S 走到 T，可以上下左右移動，但途中最多只能破壞一面牆。這讓我發現，單純記錄座標 (r,c) 已經不足以描述目前狀態，因為：(r, c, 0)：到達此	位置時還沒有使用破牆能力(r, c, 1)：到達此位置時已經使用破牆能力



&#x09;雖然兩者的位置相同，但之後可以做出的選擇不同，所以必須視為兩個獨立的搜尋狀態。因此，我在 queue 中記錄 (r,c,used)，並分別儲存兩種狀態的距離。尚未破牆時，可以選擇走進一	面牆並切換成 used = 1；已經使用能力後，則不能再進入其他牆壁。最後，我成功完成程式，並以 ST、S#T、S##T 等不同情況進行測試，確認一般通路、必須破牆與即使破牆也無法到達等	情況都能得到正確答案。



&#x09;完成三個難度後，我也進一步分析狀態數量。當只能破一面牆時，每個格子最多有兩種狀態，因此約有：

&#x09;2 × H × W個搜尋狀態。

&#x09;若延伸成最多能破 K 面牆，則會具有 K+1 種狀態，時間與空間複雜度也會相應增加。



&#x09;至此，我完成了單源 BFS、多源 BFS、二維網格 BFS，以及帶有額外狀態的 BFS 挑戰。
